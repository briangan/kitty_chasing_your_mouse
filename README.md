# About

A simple Mac utility to add an animated 2D icon of an animated object like a kitty following the mouse pointer.  The actions of the kitty would be
* Run & catch the moving mouse pointer with running animation
* When the kitty catches the mouse pointer, bite it and hold in mouth for 3 seconds and the kitty starts sitting and waiting.
* When the kitty is in eating or waiting or sleeping position, click on the kitty fades it away.
* When the kitty is waiting, scrub and pet the kitty to howl joyfully upwards slightly by swinging the mouse left and right 3 times.
* When the mouse pointer is idle for a minute or more, the kitty takes a nap next to it.

Because my knowledge of Swift framework for Mac application is only at beginner level, I'm only using AI to generate at start.  The first version of the app was generated by Claude Code Sonnet 5.5.  The initially generated codes are written messily in some legacy style with everything cramped into one file and static methods at main level instead of being defined in class such as main App.  It needs its own build script to compile the codes into .app package.  Otherwise, the use of XCode creates an app with neccary structure for IDE to run project functions.

# Usage

This is an experimental utility for fun, so you are free to [download for personal use](KittyChasingYourMouse.app).  I have not re-registered myself as Apple developer program yet, so you'd need to approve yourself by clicking Open (see popup message below by Mac OS), and drop into /Applications folders.
```
"KittyChasingYourMouse.app" is an app downloaded from the internet.  
Are you sure you want to open it?
```

After launch, a kitty icon will appear at top in your control panel icons area.  That has the menu command to Quit.  And it has command to Call the Kitty too.  [See Menu](images/menu.png)

## Version 0.6.1 - 2026/11/24 10AM EST
### AI agent used: Claude Code Sonnet 5.5

### Project planning
Prompt:
```
As you see, the current AI-created code base of this Mac OS app is entirely processed in the background without the need of IDE like XCode.  Therefore, only raw code files were created at root folder without any template of project structure or settings.  Would it be more beneficial to convert the codebase to XCode project for code and asset management, compatibility, etc.?
```

### Answer
```
Yes, but how much it helps depends on your goal. For a small app you only run yourself, the current setup is fine. If you plan to share it or keep growing it, an Xcode project is worth it.

What Xcode gives you that build.sh doesn't

App icon and assets: an asset catalog handles the icon at all required sizes. The app currently has no icon, so it shows the generic one in Finder and the Applications folder.
Signing and distribution: build.sh only does an ad-hoc codesign. Anyone else who downloads the app will hit Gatekeeper warnings. Xcode handles proper signing, hardened runtime, notarization and archiving.
Architectures: swiftc builds only for the Mac it runs on. Xcode makes universal (Apple Silicon and Intel) builds with one setting.
Settings in one place: deployment target, bundle ID, version numbers and LSUIElement live in the project instead of a heredoc inside the script.
Debugging: breakpoints, view debugging, Instruments for animation performance, and crash logs. This matters most for the tricky parts, such as cursor freezing and the overlay window.
Growth: unit tests (for example, for the scrub detection), and a place for settings UI or a login-item option.

Costs

Generated project files: an AI writing project.pbxproj by hand is error-prone. Creating the project in Xcode is more reliable, or I can write a small project spec for a generator.
Heavier tooling: you'd need full Xcode instead of just the Command Line Tools.
The private API: the cursor fix uses a private CoreGraphics call, so the app can't go on the App Store whatever tooling you use. Direct distribution with Developer ID signing is the realistic route.
```
